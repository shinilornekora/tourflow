# TourFlow

Эталон-сервис бронирования отелей для турфирмы: Go-микросервисы + React SPA.
Одна предметная область для лабораторных и курсовых по ПКП и РХД (Заманов Е. А.) и курсовой по
SPA (Клеблеева Е. Р.).

- **[docs/ARCHITECTURE.md](docs/ARCHITECTURE.md)** — сервисы, потоки, связь с лабораторными.
- **[docs/OVERVIEW.md](docs/OVERVIEW.md)** — путеводитель: путь одной брони, четыре обещания системы и чем за них заплачено, со схемами.
- **[docs/TRADEOFFS.md](docs/TRADEOFFS.md)** — 121 запись: 110 решений с альтернативой и ценой и 11 осознанных пробелов; журнал дефектов (D1–D16), указатель тем к защите.
- **[docs/LOAD.md](docs/LOAD.md)** — паспорт нагрузки (РХД ПР-1): p50/p95/p99, три повтора по 20–30 с, инварианты, все 18 прогонов; сырые выводы — `docs/evidence/raw/`.
- **[docs/TENANCY.md](docs/TENANCY.md)** — модель размещения, RLS, два уровня принуждения, отрицательные тесты (РХД ПР-2).

## Запуск (Windows, Docker Desktop)

```powershell
cd tourflow
docker compose up --build
```

Первая сборка — 3–5 минут. Затем:

| Что | Адрес |
|---|---|
| Приложение | http://localhost:3000 |
| API (gateway) | http://localhost:8080/api |
| Администратор | `admin@tourflow.local` / `Admin12345` |

Демо-данные (8 отелей в 4 городах, менеджер и клиент) заливаются скриптом. В Git Bash или WSL нужен `jq`:

```bash
./scripts/seed.sh
```

После сида: `manager@tourflow.local / Manager123`, `client@tourflow.local / Client123`.

Сквозная проверка всей системы (42 проверки по всем ролям, в том числе 10 параллельных броней одного номера; нужна запущенная система):

```bash
./scripts/e2e.sh
```

## Разработка без Docker

Нужны Go 1.24+, Node 22+, PostgreSQL 16 и Kafka. Kafka проще всего поднять контейнером:

```bash
docker compose up -d postgres kafka
```

Бэкенд — каждый сервис отдельным процессом. Переменные окружения смотрите в `docker-compose.yml`.

```bash
cd backend
go run ./cmd/identity     # и так для catalog, booking, notification, gateway
```

Фронтенд с hot reload (проксирует `/api` на `localhost:8080`):

```bash
cd frontend
npm install
npm start                  # http://localhost:3000
npm run check              # tsc + eslint + prettier
npm run build              # продакшен-сборка в dist/
npm run build:analyze      # карта бандла
```

## Тесты

```bash
cd backend
go test ./...                       # юнит-тесты и архитектурный тест
# интеграционные — на настоящем PostgreSQL. Две роли, обе НЕ суперпользователи
# (суперпользователь обходит RLS): владелец таблиц и роль данных, как в бою.
export TEST_PG_DSN="postgres://tourflow:tourflow@localhost:5432/%s?sslmode=disable"
export TEST_PG_APP_DSN="postgres://tourflow_app:tourflow_app@localhost:5432/%s?sslmode=disable"
export TEST_KAFKA_BROKERS=localhost:9092      # тесты потребителя на настоящей Kafka
go test -race -p 1 ./...
```

Интеграционным тестам нужны базы `identity_test`, `catalog_test`, `booking_test` и `notification_test`; владелец — роль `tourflow`, роли `tourflow_app` выдан `CONNECT`. Без `TEST_PG_APP_DSN` тесты идут под одной ролью, а проверки «роль данных не может снять защиту» пропускаются.

Что проверяют тесты (57 тестов; полная таблица — в конце `docs/ARCHITECTURE.md`):
- гонку за последний номер (25 параллельных броней → 1 успех) и эксперимент ПР-3: аномалия на наивном коде и четыре механизма защиты;
- пересекающиеся брони с отменами (нет овербукинга, остатки сходятся с бронями) и фоновую сверку остатков;
- идемпотентность: параллельные повторы, сохранённый ответ команды, конфликт под прежним ключом;
- outbox: фиксацию и откат вместе с бронью, аренду ретранслятора, изоляцию очереди, отказ записать событие о чужой брони, отсутствие события у отклонённой команды;
- RLS под ролью данных: отрицательные тесты прямым SQL в booking, catalog и notification, отсутствие утечки контекста через пул; уровень приложения отдельно — при выключенных политиках;
- неизменяемость и неподделываемость журнала аудита;
- компенсацию при отключении отеля, дубли и устаревшие события;
- потребителя на настоящей Kafka: poison pill → DLQ, временная ошибка, отказ публикации в DLQ, падение после коммита, эволюция контракта и карантин незнакомой версии схемы;
- ротацию refresh-токенов с обнаружением кражи, права ролей, поиск;
- оптимистические блокировки правок каталога;
- circuit breaker и rate limit, в том числе подмену `X-Forwarded-For`.

Нагрузочный замер — `docs/LOAD.md`.

## Структура

```
backend/
  cmd/{gateway,identity,catalog,booking,notification}/   точки входа, ручной DI
  internal/<service>/{domain,app,store,api,migrations}/  гексагональная архитектура
  internal/platform/                                     общая инфраструктура
  arch_test.go                                           сервисы не импортируют друг друга
  tools/loadgen/                                         генератор нагрузки (docs/LOAD.md)
frontend/
  src/app            store, роутер, тема, layout
  src/shared/api     RTK Query: baseApi с refresh, эндпоинты, типы
  src/features/auth  сессия, guards (RequireAuth / RequireRole)
  src/pages          страницы (каждая — отдельный чанк)
  webpack/           common / dev / prod
deploy/postgres/init.sql   базы и роли-владельцы (первый старт)
deploy/postgres/roles.sql  роли данных (каждый старт, идемпотентно)
scripts/                   seed.sh, e2e.sh, load/{fill.sql,run_all.sh}
docs/                      ARCHITECTURE.md, TRADEOFFS.md, LOAD.md, TENANCY.md, evidence/raw/
```

## Страницы SPA

| Страница | Кому |
|---|---|
| Каталог с фильтрами, сортировкой и пагинацией | всем |
| Отель: свободные номера на даты, бронирование | всем (бронирует только клиент) |
| Вход / Регистрация | гостям |
| Личный кабинет (профиль, смена пароля) | всем вошедшим |
| Уведомления | всем вошедшим |
| Мои брони («корзина»: предстоящие, история, отменённые) | клиенту |
| Мои отели / Управление отелями | менеджеру / админу |
| Создание и редактирование отеля, менеджеры, статус | админу (менеджер — только редактирование своих) |
| Создание и редактирование категории номеров | менеджеру своего отеля, админу |
| Брони отелей (с отменой и причиной) | менеджеру, админу |
| Журнал аудита отеля | менеджеру, админу |
| Пользователи и роли | админу |
| 404, 403 | — |
